### 2026-10-05 · REV-1.2 decisions

- The initially observed setup recovery prerequisite gap was real: the old guard loses its in-memory restore phase on restart and exempts auth writes. Resolve **bootstrap only** with a monotonic `storage/setup-authority.json` receipt outside the DB, plus conservative maintenance-lock checks and atomic DB owner/claim creation. A reserved/corrupt/mismatched receipt or emptied initialized DB is administrative recovery, never fresh setup. This does **not** implement or close REV-2.2's general writer fence/restore journal (F-11 remains open).
- Receipt claim is exclusive before DB commit; owner+DB marker/claim commit atomically. Interrupted/uncertain commits stay closed, and only matching persisted claim+owner epoch permits reconciliation. File/parent sync are used; Windows's unsupported directory fsync is explicitly not a Linux power-loss pass. Preserve the receipt across restore/container recreation; no automated marker deletion or password-update loser branch.
- Require configured `NUXT_APP_ORIGIN` in production, exact scheme/host/port, no forwarded-origin trust. Missing browser metadata is not assumed non-browser: explicit non-simple `X-PandaBlog-Client: non-browser` is required for metadata-less API mutation clients. Credentialed wildcard CORS is unsupported.
- Five-minute recent-auth proof uses sealed **secure.authenticatedAt**, not mutable display/profile timestamps; current password is an alternative. Full-session enrollment needs that proof; epoch-bound forced enrollment remains a narrow exception. Security changes revoke the caller and trusted devices; both locales and client refresh/reenrollment flows are updated.

### 2026-10-06 · Phase 3 decisions

- Operational media ceilings are 128-MiB request / 32-MiB file / 20 files, reduced by stored settings, with 5 staging requests and 512-MiB combined input quota. Invalid/over-limit ingestion rejects the entire request before publication; successful ingestion preserves existing media `{results}` and admin record responses. Native/disk execution is not falsely cancelled by caller expiry.
- Use a conservative global publication/deletion/snapshot serializer (1 active/4 waiting), which also serializes equal hashes without retaining an unbounded keyed lock map. DB ownership precedes shared paths; destination-mount exclusive hard links plus retained claim-specific inode witnesses allow proof-based interrupted publication retirement. Unknown existing objects refuse recovery, never loser-cleanup deletion.
- Regex executes only in SurrealDB's linear-time Rust engine; bounded V8 compilation validates syntax but never matches a user subject. Fuzzy recall deliberately uses finite candidates/vocabulary/work and exposes `search_truncated`; exact FTS recall remains scope-filtered before limit. Ordinary pages retain WITH NOINDEX; no new index performance claim is made.
- Legacy metadata clipping is explicit (`metadata_truncated`); detail is fetched separately before editing. Facets cap at 200 with `truncated`. New metadata accepts 32 tags/folders and finite JSON/string sizes. en/zh-CN warnings coordinate incomplete cleanup, suggestion/facet/legacy-display limits.
- Legacy objects migrate to ready without changing bytes/settings/owners, but reference_safe remains false: old duplicate counts and absent historical/avatar tracking cannot authorize deletion. All API/force deletion refuses those objects pending a reviewed complete reconciliation on an approved copy. New duplicates do not fabricate references; private or conflicting-scope dedup never changes ownership/visibility.
- Source reservations precede post/cover/block/avatar/version-restore and public site settings writes. Bare document hashes, block IDs and foreign asset filenames are not mistaken for media; canonical/legacy media references use the serving layer's bounded double-decode contract. Public setting reservations exclude secret/admin-only material. Removed current post references and replaced avatars conservatively retain reservations, including failed/ambiguous saves; post hard deletion releases only after all current/version source blocks are gone. This is a deliberate storage-availability tradeoff, not an exact garbage-collection/reconciliation claim.
- Snapshot packing shares publication ownership and refuses incomplete object claims, preventing `.owned`/partial generations entering a new snapshot. Existing maintenance/uncertainty authority still fences unclean app restarts; media repair does not auto-steal writer receipts. Full crash/power-loss and mixed-load acceptance remain Phase 5/operator gates.
